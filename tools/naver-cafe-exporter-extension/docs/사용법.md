# 네이버 카페 게시글 원문 추출기 사용법

## 목적

이 Chrome 확장 프로그램은 네이버 카페에서 내가 볼 수 있는 게시글 목록을 수집하고, 각 게시글 본문을 하나의 Markdown 파일로 저장합니다.

요약은 확장 프로그램 안에서 만들지 않습니다. 원문을 먼저 보존한 뒤 NotebookLM 같은 도구에 넣어 요약, 질문 생성, 개념 정리를 진행하는 흐름을 권장합니다.

## 왜 요약을 바로 만들지 않는가

자동 요약은 편하지만, 본문 추출이 완전히 검증되지 않은 상태에서는 틀린 요약이 그럴듯하게 보일 수 있습니다.

먼저 확인할 질문은 이것입니다.

- 저장된 Markdown 파일의 `# Original Body`가 실제 게시글 본문과 같은가?
- 빠진 코드 블록, 이미지 설명, 긴 문단이 없는가?
- 카테고리와 URL, articleId가 원문과 연결되어 있는가?

이 검증을 통과한 뒤 NotebookLM에 넣는 편이 더 안전합니다.

## 설치 방법

1. Chrome 주소창에 `chrome://extensions`를 입력합니다.
2. 오른쪽 위 `개발자 모드`를 켭니다.
3. `압축해제된 확장 프로그램을 로드합니다`를 클릭합니다.
4. 아래 폴더를 선택합니다.

```text
tools/naver-cafe-exporter-extension
```

## 사용 순서

1. Chrome에서 네이버 카페에 로그인합니다.
2. 내가 쓴 글 목록 또는 추출하려는 게시글 목록 화면을 엽니다.
3. 확장 프로그램 아이콘을 클릭합니다.
4. `Collect`를 눌러 현재 화면의 게시글 목록을 수집합니다.
5. 수집 개수가 화면의 게시글 개수와 맞는지 확인합니다.
6. `Document`를 눌러 각 게시글 본문을 추출합니다.
7. `Files`를 눌러 게시글 하나당 Markdown 파일 하나씩 저장합니다.

## 버튼 설명

- `Collect`: 현재 네이버 카페 화면에서 게시글 목록을 수집합니다.
- `Document`: 수집된 게시글을 하나씩 열어 본문 원문을 추출합니다.
- `JSON`: 현재 결과를 JSON 파일 하나로 저장합니다.
- `CSV`: 현재 결과를 CSV 파일 하나로 저장합니다.
- `MD`: 현재 결과를 Markdown 파일 하나로 합쳐 저장합니다.
- `Files`: 게시글 하나당 Markdown 파일 하나씩 저장합니다.

## 저장되는 파일 예시

`Files` 버튼을 누르면 다음과 같은 형태의 파일들이 저장됩니다.

```text
naver-cafe-articles-2026-05-07T06-20-00-000Z/
01-62273-2026 05 06 개발일지 문서 객체화 공유하기.md
02-62262-2026 05 05 개발일지 Claim check 프로젝트 적용.md
03-62261-2026 05 05 개발일지 Buffer 종류.md
```

각 Markdown 파일은 아래 구조를 가집니다.

```md
---
title: 게시글 제목
url: https://cafe.naver.com/ArticleRead.nhn?clubid=...
articleId: 62273
clubId: 28969626
category: 게시판 이름
sourceType: rendered-tab
extractedAt: 2026-05-07T06:20:00.000Z
---

# Original Body

게시글 본문 원문...
```

## NotebookLM에 넣는 방법

1. `Files`로 저장된 Markdown 파일들을 확인합니다.
2. 본문이 정상적으로 들어간 파일만 골라 NotebookLM에 업로드합니다.
3. NotebookLM에서 요약, 질문, 핵심 개념, 학습 노트 생성을 요청합니다.

추천 프롬프트 예시는 아래와 같습니다.

```text
이 Markdown 파일들은 네이버 카페에 작성한 개발일지 원문입니다.
각 문서를 다음 형식으로 정리해 주세요.

1. 주제
2. 핵심 개념
3. 내가 배운 점
4. 아직 검증해야 할 질문
5. 다음 실험 또는 구현 과제

원문에 없는 내용은 추측하지 말고, 추측이 필요한 부분은 "검증 필요"로 표시해 주세요.
```

## 로그 확인 방법

popup의 `Run Log`에서 추출 상태를 확인할 수 있습니다.

성공 예시:

```json
{"articleId":"62273","bodyLength":5230,"fallback":"rendered-tab"}
```

확인할 점:

- `bodyLength`가 너무 작으면 본문이 제대로 추출되지 않았을 수 있습니다.
- `fallback:"rendered-tab"`은 실제 렌더링된 게시글 화면에서 본문을 읽었다는 뜻입니다.
- 실패가 반복되면 게시글이 비공개, 삭제됨, 권한 부족, 또는 네이버 카페 DOM 변경 상태일 수 있습니다.

## 현재 설계 원칙

- 확장 프로그램은 원문 추출과 저장까지만 책임집니다.
- 요약과 해석은 NotebookLM 같은 전문 도구로 넘깁니다.
- 원문 검증 없이 요약 결과를 신뢰하지 않습니다.
- 게시글 하나는 Markdown 파일 하나로 분리합니다.
